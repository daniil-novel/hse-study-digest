# Smart LMS через API: как получить сроки непосредственно из курса

Эта глава для случая, когда ВШЭ уже предоставила вам разрешение на чтение календаря через Moodle Web Services и выдала личный токен. Токен — секретная строка, по которой сервер узнаёт программу и проверяет её права. Для обычного входа в Smart LMS достаточно университетской учётной записи. Доступ к API оформляется отдельно. Публичного подтверждения, что такой доступ автоматически получает каждый студент ВШЭ, мы не нашли. Если у вас только обычный вход, пройдите [основной маршрут](../README.md) или [упражнение с файлом календаря](lms_calendar.md).

## Какой результат получится

Допустим, в вашем ИУП есть «Анализ данных». Вы добавили в настройки ID соответствующего курса. При каждом запуске программа запрашивает у Smart LMS календарь заданий этого курса на ближайшие 90 дней. Из ответа она выбирает видимые события сдачи для Moodle-заданий типа Assignment. Тест, лекция и открытие приёма работ имеют другие типы. Для них используйте предусмотренные практикумом дополнительные источники.

После успешного запроса одна строка в общей таблице содержит название предмета, название задания, дату и время сдачи в Москве и ссылку на карточку. Например, срок в вымышленном задании «Отчёт по лабораторной» установлен на 17:59 UTC. В таблице будет 20:59 МСК в тот же день. Сверьте это время со своей карточкой задания, особенно если преподаватель согласовал индивидуальное продление.

## Как подключить один курс

1. **Уточните права токена.** В документации выданного сервиса или у ответственного за Smart LMS проверьте, что доступны протокол REST и функция чтения `core_calendar_get_action_events_by_course`. REST здесь означает, что программа посылает обычный HTTPS-запрос и получает ответ в формате JSON. У Moodle разрешения определяются настройками конкретного сервиса. [О веб-сервисах Moodle](https://docs.moodle.org/en/Using_web_services)
2. **Найдите ID курса.** Откройте главную страницу дисциплины в Smart LMS. В адресе вида `https://edu.hse.ru/course/view.php?id=12345` число после `id=` обозначает курс. Здесь и ниже 12345 — вымышленный пример. На странице отдельного задания адрес выглядит как `/mod/assign/view.php?id=...`. Там число обозначает карточку работы. Вернитесь на страницу курса и возьмите число из её адреса.
3. **Проверьте название.** Откройте `private/courses.json` и посмотрите, как записан ваш предмет. Скопируйте название целиком. Это связывает курс Moodle с той же дисциплиной, которая уже используется при обработке групп и заметок.
4. **Свяжите номер с предметом.** Откройте `private/settings.json`. Установите значение поля `lms_api_courses` по образцу ниже. Если в файле, созданном ранее, поля ещё нет, добавьте его внутрь внешних фигурных скобок. Свойства одного объекта разделяются запятыми. Убедитесь, что настройки почты и выбранных чатов вы сохранили.

   ```json
   "lms_api_courses": {"12345": "Анализ данных"}
   ```

   Это одна строка внутри настроек. Кавычки вокруг номера обязательны, потому что он служит ключом словаря JSON. Для второго курса добавьте вторую пару внутри тех же скобок, через запятую. На первом запуске проще проверить один.

5. **Сохраните токен на своём компьютере.** В «Пуске» найдите «Изменение переменных среды текущего пользователя». В разделе пользовательских переменных нажмите «Создать». В поле имени введите `HSE_LMS_TOKEN`, в поле значения вставьте выданный вам токен. Закройте окна кнопкой «ОК», откройте новое окно PowerShell в папке проекта. Переменная доступна программам, которые работают от вашего пользователя. При прекращении доступа отзовите токен у выдавшего его сервиса. Не включайте окно с его значением в видеоотчёт.
6. **Запустите пробный сбор.** Введите `python study.py run`. Слово `python` запускает интерпретатор, `study.py` указывает ему главный файл, а `run` собирает местную таблицу. Для этой ветки достаточно стандартного Python и доступа к сети. Настройка языковой модели на импорт по API не влияет.
7. **Проверьте один настоящий срок.** Откройте `out/live/digest.html`, найдите свой предмет и перейдите на карточку из колонки «Источник». Сверьте название и время, учитывая часовой пояс в интерфейсе Moodle. Если в курсе пока нет заданий с подходящим сроком, пустая выборка ожидаема. Для первого опыта удобнее выбрать курс с уже знакомым открытым заданием.

Чтобы отключить запросы, верните `"lms_api_courses": {}` в настройках. Для проверки этого адаптера без реальной учётной записи используйте упражнение с тестами ниже.

## Как устроен модуль

Исходный код находится в [lms_api.py](https://github.com/daniil-novel/hse-study-digest/blob/670aa644cd3d2edf0548427b09f3eb998f549e33/lms_api.py). Главная программа передаёт функции `read_tasks` три значения: выбранные номера курсов с названиями предметов, справочник дисциплин и текущее время.

1. Сначала модуль проверяет настройки. Названия должны присутствовать в справочнике, а номера должны быть положительными целыми. При опечатке студент получает сообщение до публикации таблицы.
2. Программа обращается по фиксированному адресу `https://edu.hse.ru/webservice/rest/server.php`. Название функции, токен, номер курса и временные границы передаются в теле запроса POST. Переход по перенаправлению запрещён, чтобы токен не ушёл на другую страницу. На этом этапе модель не вызывается.
3. Сервер может выдавать ответ частями. После каждой порции адаптер получает ID последнего события и продолжает чтение, пока не дойдёт до конца. Ошибка доступа, повреждённый ответ или зацикливание прерывают сбор. Это важно для письма: если сервис недоступен, вы увидите ошибку вместо сводки с молча пропущенной дисциплиной.
4. Модуль проверяет принадлежность события выбранному курсу, его видимость, тип задания и срок. В формате календарных событий Moodle 4.5 поле `instance` содержит ID модуля курса для построения ссылки на карточку. Личные ключи к адресу карточки не добавляются. [Описание функции Moodle](https://github.com/moodle/moodle/blob/MOODLE_405_STABLE/calendar/externallib.php) · [Формат события в Moodle](https://github.com/moodle/moodle/blob/MOODLE_405_STABLE/calendar/classes/external/event_exporter_base.php)
5. В общую таблицу попадают те же поля, что у записи из календарного файла: `course` — предмет, `task` — что сделать, `due` — срок в Москве, `source` — откуда взята запись, `url` — карточка задания. После этого работают общие правила вывода и подготовки письма. [Как строится таблица](study_report.md)

### Как читать код сверху вниз

Сначала найдите `ENDPOINT`, `METHOD` и `PAGE_SIZE`. Это адрес сервера, имя операции и размер одной порции — до 50 событий. В `fetch_page` готовится и отправляется **один** запрос. Если ответ похож на страницу входа, превышает 5 МБ или содержит сообщение об отказе, функция поднимает ошибку без вывода ответа сервера и секретов.

Следующая функция, `course_events`, собирает порции одного курса. Начальный указатель равен нулю. Затем программа передаёт серверу `lastid` — номер последнего увиденного события. Пустая порция завершает обход. Если сервер повторил ID или вернул несовместимый указатель, функция прекращает обработку. Есть также предел в 100 порций на курс, чтобы неисправный сервис не удерживал сбор бесконечно.

Последняя функция, `read_tasks`, отвечает на вопрос «что из полученного действительно является заданием с дедлайном?». Для вымышленного события с `modulename=assign`, `eventtype=due` и `visible=1` она проверяет курс, время и ID карточки. Если всё совпало, операция даёт одну строку. Если взять ту же запись и заменить тип на `open` (открытие приёма), в таблицу она не попадёт. Так можно объяснить напарнику, почему на один и тот же курс приходят разные календарные события.

## Как проверить без токена

В папке проекта выполните одну команду.

```text
python -m unittest discover -s tests -p test_lms_api.py -v
```

`-m unittest` запускает встроенную в Python программу проверки, `discover` просит её найти тесты, `-s tests` задаёт папку поиска, `-p test_lms_api.py` выбирает файл, `-v` печатает название и результат каждой проверки. В [файле тестов](https://github.com/daniil-novel/hse-study-digest/blob/670aa644cd3d2edf0548427b09f3eb998f549e33/tests/test_lms_api.py) сервер заменён функцией с вымышленным ответом. Так можно проверить выбор событий, создание ссылок и обработку ошибок без обращения к ВШЭ. Строка `OK` означает, что испытания с этими примерами прошли. Подтвердить права конкретного студента можно только шагами 6–7.

| Что вы видите | Что проверить |
|---|---|
| Сбор сообщает, что токен не задан | Название переменной и новое окно терминала. Значение токена выводить на экран не нужно. |
| Сервер отклонил запрос или вернул страницу входа | Есть ли у токена право именно на указанную функцию и курс. Уточните у выдавшего токен сервиса. |
| В таблице нет ожидаемого задания | Проверьте курс, доступность задания именно под вашим аккаунтом, вид деятельности и попадание срока в ближайшие 90 дней. |
| Через API и календарный файл появились похожие строки | Перейдите к оригиналу и сравните формулировки. Если два источника полностью покрывают одни и те же задания, оставьте для этого упражнения один из них. |
