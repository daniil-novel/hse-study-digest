# Как устроен учебный дайджест

[Запуск и настройка проекта](../README.md) · [Собрать короткую цепочку своими руками](build.md)

Представьте, что в группе написали «Сдать план проекта до 18.11.2026», в календаре стоит время пары, а вы записали «Уточнить требования к плану». У этих трёх записей разный смысл. Программа сохраняет происхождение каждого поручения, оставляет неопределённость там, где её нельзя устранить, и показывает в таблице, что стоит проверить. В этих главах можно проследить путь от исходной фразы до письма и изменить один этап, сохранив остальные.

## Откуда берутся строки таблицы

| Источник | Что попадает на вход | Кто принимает решение |
| --- | --- | --- |
| Выбранная группа или канал Telegram | Недавние текстовые сообщения за два календарных месяца и названия подтверждённых студентом дисциплин | Студент выбирает чаты. Локальные функции выделяют кандидатов из текста. |
| Календарь SmartLMS | Событие с явным указанием срока или задача календаря; название дисциплины должно распознаваться | Календарный модуль проверяет тип, формулировку, предмет и часовой пояс. |
| Прямой запрос SmartLMS, дополнительная ветка | Выданный вузом токен и явно заданные номера курсов. Программа читает разрешённые для студента события заданий на ближайшие 90 дней. | Модуль API проверяет тип события и принадлежность курсу, передаёт срок в московском времени. |
| Личная заметка участника | Текст, предмет, собственный ID записи и ссылка на первоисточник | При включённом облачном режиме модель выбирает дословное поручение. Python проверяет цитату и извлекает дату. В локальном режиме работают правила. |

Из каждого источника получается строка с одинаковыми пятью полями. Внешние сервисы описаны отдельно, поэтому можно начать с одной заметки, затем добавить курс с календарём и только затем — свою учебную группу. Студенту не нужно настраивать всё сразу, чтобы увидеть, где возникла ошибка.

## Как читать Python, если вы видите его впервые

| Обозначение в коде | Как прочесть его на нашем примере |
| --- | --- |
| `def` и имя с круглыми скобками | Здесь программист определил функцию — отдельное действие. В `def exact_due(text)` функция принимает текст. Она начнёт работать только при вызове, например `exact_due("Дедлайн 09.11.2026")`. |
| `return` | Вернуть результат вызывающей функции. Дата, которую вернула `exact_due`, затем оказывается в поле `due`. |
| `if` | Проверить условие. Например, отправитель вызывается только для команды `send`. |
| `for` | Повторить действия для каждого элемента. Та же проверка применяется сначала к одному, затем к следующему событию календаря. |
| `[]` | Контекст важен. Пустые скобки означают пустой список, а запись `rows[0]` означает первый элемент уже полученного списка. |
| `{}` и `row["course"]` | Фигурные скобки образуют словарь, где каждому ключу соответствует значение. Из одной записи выражение `row["course"]` получает название предмета. |
| `async` и `await` | Программа может ожидать ответ Telegram по сети. `await` указывает, результат какого запроса требуется дождаться. Настраивать потоки исполнения для этой практики не нужно. |
| `raise ValueError` | Остановить данную операцию с объяснением, что значение неподходящее. Например, неизвестный курс в личной заметке должен быть исправлен до подготовки письма. |
| JSON, CSV, HTML, ICS | JSON хранит небольшие списки и настройки, CSV — строки таблицы, HTML — страницу для чтения, а ICS — календарные события и задачи. Открытие файла в редакторе не меняет его формат. |

Если вы хотите найти описанное место, откройте нужный файл в репозитории или текстовом редакторе, нажмите Ctrl+F и введите полное имя функции из главы. Сначала найдите её входные параметры, потом строки с `return` или записью файла. Разбор на примере из главы покажет, какие из промежуточных условий сработали.

## В каких условиях проверяли практикум

4 ноября 2026 года на Windows с Python 3.11.5, Telethon 1.45.0 и icalendar 7.3.0 прошли 18 автоматических проверок. Демо выдало четыре строки. На подписочном Codex CLI 0.144.1 дважды проверяли разные операции: отбор вымышленных групп по предмету и извлечение поручения с точным сроком. При сборке с настоящим вызовом модели и вымышленным календарём в итоговую таблицу попали две строки из двух источников.

Проверки адаптеров Telegram, университетского API и почты выполнялись с имитацией ответов сервисов. Работу личных подключений подтвердите по критериям в главном руководстве. Для Claude Code 2.1.302 проверены параметры запуска и обработка истёкшего входа. Успешный ответ через свой аккаунт можно подтвердить командой `python study.py probe claude`: она передаёт только учебный пример.

## Что меняется с течением времени

У проекта три разных отсчёта времени. В Telegram окно в два календарных месяца ограничивает историю, которую читают при очередном запуске. Оно не ограничивает даты выполнения поручений. В календаре SmartLMS за диапазон событий отвечает выбранный при экспорте период, а у локального файла есть момент скачивания. Планировщик Windows определяет, когда запустить новую сборку. По умолчанию практикум предлагает понедельник и четверг. За повторную отправку одного письма в тот же почтовый период отвечает журнал SQLite. [Как устроена отправка](study_report.md)

Можно увидеть все доступные источники и всё равно не найти домашнюю работу. Сообщение могло содержать только картинку, предмет мог называться иначе, преподаватель мог опубликовать задание без даты, а в личной заметке модель могла пропустить поручение. На сдаче практики возьмите один известный первоисточник, покажите его строку и поясните, на каком этапе возникнет расхождение, если изменить формулировку или дату.
