# Как основной файл соединяет части программы

[Оглавление](README.md) · [Открыть код](https://github.com/daniil-novel/hse-study-digest/blob/670aa644cd3d2edf0548427b09f3eb998f549e33/study.py)

Файл `study.py` нужен для того, чтобы у студента была одна точка входа. Вы выбираете действие коротким словом, а функция `main` определяет, какие части программы нужны и в каком порядке их вызвать. Подключённые модули возвращают объекты Python друг другу в памяти. Студенту не нужно вручную пересылать файлы между ними на каждом запуске.

## 1. Выберите действие

Все команды в таблице вводятся из папки проекта. Первое слово `python` запускает интерпретатор. Второе, `study.py`, указывает файл программы. Следующее слово выбирает операцию. При `auth` и `probe` в конце также указывается имя установленного клиента.

| Команда | Что произойдёт | Как увидеть результат |
| --- | --- | --- |
| `python study.py demo` | Прочитает вымышленные данные из `example.json` и пропустит их через локальные правила. | В `out/demo` появятся HTML и CSV. Аккаунты и сеть не нужны. |
| `python study.py setup` | Создаст закрытую рабочую папку и начальные файлы данных. | В `private` появятся `settings.json`, `courses.json` и `lms.json`. Функция сохраняет уже существующие файлы. |
| `python study.py login` | Откроет вход Telegram для адаптера чтения. | После успешного входа в `private` появится файл сессии. |
| `python study.py discover` | Подготовит таблицу возможных учебных чатов из метаданных диалогов. | Откройте `private/candidates.csv` и выберите свои группы. |
| `python study.py auth codex` | Настроит вход в клиент модели под подпиской участника. | Завершите процедуру в официальном интерфейсе. Для Claude Code замените `codex` на `claude`. |
| `python study.py classify-demo codex` | Передаст клиенту две вымышленные дисциплины и три вымышленные группы; попросит выбрать учебные группы по содержанию. | Две учебные группы должны получить правильные предметы, группа о прогулке должна быть исключена. Для другого клиента укажите `claude`. |
| `python study.py probe codex` | Отправит одну **вымышленную** заметку в выбранный клиент. Проверит, вернул ли он цитату с ожидаемым сроком. | Дождитесь сообщения об успешном тесте. Для Claude Code в последнем слове укажите `claude`. |
| `python study.py run` | Соберёт включённые источники и пересоздаст локальный отчёт. | Откройте `out/live/digest.html` и `out/live/digest.csv`. |
| `python study.py send` | Заново соберёт отчёт и при включённой отправке передаст HTML на собственную почту. | Сверьте результат с письмом и локальной таблицей. Повтор в том же почтовом периоде ограничивает журнал доставок. |

`demo`, `setup` и отдельные команды модели (`auth`, `classify-demo`, `probe`) выполняются без чтения личных настроек курсов и чатов. Для рабочего сбора из своих источников сначала выполните `setup`. Помощь программы можно получить командой `python study.py --help`. Два дефиса и слово `help` просят показать допустимые операции.

## 2. Прочитайте настройки глазами программы

`ROOT` обозначает папку, где расположен файл `study.py`. Отсюда программа строит пути к `private` и `out`. Функция `read` читает UTF-8 JSON, в том числе файлы с меткой кодировки Windows. Если файл отсутствует или в нём лишняя запятая, программа сообщит, какой файл проверить.

| Где и что лежит | За что отвечает проверка |
| --- | --- |
| `private/courses.json` | `config` проверяет непустой словарь дисциплин. Для каждого названия задаётся список непустых вариантов названия либо пустой список. |
| `private/settings.json` | `config` проверяет поставщика, тип списка сопоставлений чатов, логические переключатели почты и облака и строку календаря. В JSON слова `true` и `false` пишутся строчными буквами без кавычек. |
| `private/lms.json` | `own_notes` читает список подготовленных студентом заметок. Пустой список допустим. Каждая заметка должна иметь строковые поля `id`, `course`, `text`, `url`, уникальный непустой ID, предмет из словаря и текст от 1 до 8000 знаков. |
| Поле `chats` | Здесь студент сопоставляет выбранные ID групп с официальными предметами. Сам файл `candidates.csv` не включает группу автоматически. |
| Поле `lms_calendar` | Пустая строка отключает календарь. Путь к файлу или личная ссылка подключает его, если установлен пакет для календаря. |
| Поле `lms_api_courses` | Пустой словарь отключает прямой запрос SmartLMS. Если вуз выдал нужный токен, укажите соответствия номеров курсов названиям из ИУП. [Подключение и проверка API](lms_api.md) |
| Поле `allow_cloud` | Определяет способ разбора личных заметок. При `false` используются локальные правила. При `true` вызывается выбранный клиент модели. |
| Поле `email_enabled` | Разрешает команду `send`. Само изменение на `true` не отправляет письмо и не создаёт расписание в Windows. |

## 3. Как проходит личный запуск

1. `main` распознаёт команду. При запуске `send` с выключенной отправкой останавливается до чтения источников.
2. `own_notes` проверяет локальный список заметок. Если нет заметок, выбранных чатов, календаря и курсов для API, у пользователя есть конкретная ошибка настройки вместо пустой сводки.
3. Если есть выбранные чаты, `telegram` собирает записи из них. Если есть календарь, `calendar_rows` просит `lms_calendar.read_tasks` разобрать его, проверяет названия предметов и формат дат, затем добавляет календарные записи. Если настроено чтение API, `lms_api.read_tasks` добавляет строки заданных курсов отдельным шагом.
4. Личные заметки попадают в `extract` либо `from_text` в зависимости от `allow_cloud`. Модель получает только тексты личных заметок. Записи Telegram, календаря и API приходят напрямую в итоговый список.
5. `render` превращает список в два файла. Для `run` это конец. Для `send` HTML передаётся в `deliver`, которая проверяет период и почтовые настройки. Если один из сборщиков сообщил об ошибке, запуск останавливается до отправки.

Пример. У участника одна своя заметка, а `chats` пуст и `lms_calendar` пуст. Вызов `run` при `allow_cloud: false` (логическое значение в JSON) прочитает заметку, применит правила, а затем запишет отчёт. Такой запуск уже проверяет полный локальный путь данных и позволяет отладить его до получения разрешений на другие источники.

## 4. Как устроено демо

`demo` берёт часы из [example.json](https://github.com/daniil-novel/hse-study-digest/blob/670aa644cd3d2edf0548427b09f3eb998f549e33/example.json). Датой эксперимента всегда будет 4 ноября 2026 года. Благодаря этому пример даёт одинаковый результат через месяц и через год. Он обрабатывает синтетические заметки и разрешённые учебные группы, отсекает старое и личное сообщения и передаёт записи в тот же `render`, что и рабочий запуск.

В исходном демо получается четыре строки. Отчёт по лабораторной встречается дважды и сохраняется со ссылкой на два обозначения источника. Для плана проекта остаются обе даты со статусом проверки. У разбора кейса остаётся неопределённый срок «до пятницы». Автономное демо не обращается к абонентской подписке. Для проверки именно живого клиента служит `probe`.

## 5. Если запуск завершился ошибкой

Сначала прочитайте сообщение за словами «Сбор остановлен». Найдите стадию — настройки, получение данных, проверка цитаты, запись файлов, почта. Затем выполните минимальную подходящую операцию из первой таблицы. Например, `demo` проверяет локальную запись отчёта, а `probe` отдельно проверяет модель. Исправив стадию, снова выполните `run` и проверьте дату изменения файлов. Старый отчёт на диске может сохраниться после ошибки, поэтому наличие файла само по себе не доказывает успех последней попытки.
