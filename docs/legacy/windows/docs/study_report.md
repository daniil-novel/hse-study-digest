# Как собрать таблицу и отправить ровно одно письмо за период

[Оглавление](README.md) · [Открыть код](https://github.com/daniil-novel/hse-study-digest/blob/670aa644cd3d2edf0548427b09f3eb998f549e33/study_report.py)

Модуль получает список записей одинаковой формы от разных источников. Он сопоставляет записи, сохраняет таблицу на диск и, только когда выбран режим отправки, передаёт копию HTML-версии почтовому серверу. Форматы CSV и HTML нужны для разных способов проверки. Первый открывается в табличном редакторе, второй — в браузере и в почтовом клиенте.

## 1. Как сравниваются записи

У каждой записи есть предмет, текст поручения, срок, источник и ссылка. В `table` программа приводит последовательности пробелов к одному пробелу и игнорирует регистр букв при сравнении. В записях с известным сроком из сравниваемого текста удаляется распознаваемая дата. Когда срок неизвестен, весь текст остаётся частью сравнения. Получается основа для сравнения — предмет плюс оставшийся текст. В отчёте сохранена исходная формулировка с нормализованными пробелами.

Для разминки возьмите три вымышленных сообщения по одному предмету.

| Исходная строка | Срок, переданный сборщиком | Как используется |
| --- | --- | --- |
| «Сдайте отчёт до 09.11.2026» из источника А | 2026-11-09 | Начинает строку таблицы. |
| «Сдайте отчёт до 09.11.2026» из источника Б | 2026-11-09 | Добавляет к этой строке второй источник. |
| «Сдайте отчёт до 11.11.2026» из источника В | 2026-11-11 | Образует вторую строку и показывает расхождение по сроку. |

На выходе две строки со статусом «Сверить разные сроки». Программа не выбирает дату, только показывает, в каких источниках она встретилась. У двух разных задач может быть одинаковая краткая формулировка, поэтому специалист по предмету должен проверить смысл. Обратная ситуация тоже возможна. «Сдайте отчёт» и «Пришлите отчёт» различаются для алгоритма, даже если преподаватель говорил об одной работе.

При отсутствии конфликта запись с датой получает статус «Срок указан», без даты — «Уточнить по источнику». В таблице неизвестный срок отображается как «Не уточнён». Сначала идут известные сроки по возрастанию, после них идут строки без срока. Статус относится к указанной дате и не означает, что студент уже выполнил работу. Программа не ставит за него отметку о сдаче.

## 2. Откуда берутся два файла

1. `render` вызывает `table` и из готовых строк делает две версии одного результата.
2. `link` отбрасывает адреса неизвестных сайтов, ссылки с идентификационными данными и адреса с распознаваемыми параметрами доступа. Источник без пригодной ссылки остаётся обычным текстом. В HTML ссылка скрыта за названием источника, а CSV отделяет ссылку от названия.
3. `csv_text` создаёт текст с разделителем `;`. Если ячейка начинается с символа формулы, программа добавляет перед ним апостроф. Это помогает табличному редактору увидеть текст задания, а не вычисляемую формулу. Файл записывается в UTF-8 с меткой кодировки для совместимости с Excel.
4. В HTML потенциальная разметка внутри задания заменяется текстовыми представлениями символов. Например, если преподаватель написал теги HTML, они будут видны как часть задания.
5. `write` сохраняет **каждый** файл через временный соседний файл и затем заменяет готовый. Поэтому при сбое записи одного файла его предыдущее целое содержимое не будет заменено половиной текста. Два файла сохраняются последовательно. Если второй не обновился, устраните ошибку и повторите запуск.

В отчёте без записей останется заголовок и пояснение об отсутствии найденных кандидатов. Такая таблица не устанавливает отсутствие заданий во всех курсах. Откройте известное задание и проверьте диапазон и состояние источника, особенно после изменений конфигурации.

## 3. Что обозначают понедельник и четверг

Внешний планировщик решает, **когда** запускать программу. `deliver` решает, **отправлялось ли уже письмо за данный период**. Для понедельника, вторника и среды номер периода берётся по дате предшествующего или сегодняшнего понедельника. Для четверга, пятницы, субботы и воскресенья — по дате четверга. Второй запуск во вторник после успешного понедельника не создаст повторного письма на тот же ящик.

Пример. Понедельник 9 ноября 2026 года и среда 11 ноября относятся к периоду 9 ноября. Четверг 12 ноября открывает следующий период. Запуск только команды формирования локальной таблицы не расходует ни один почтовый период. Даже при правильно заданном графике локальный компьютер должен быть доступен планировщику. Параметры пропущенного запуска выбираются в самом планировщике.

## 4. Что происходит при отправке

`deliver` проверяет переменные `DIGEST_EMAIL`, `DIGEST_SMTP_HOST` и `DIGEST_SMTP_PASSWORD`. Это адрес студента, имя почтового сервера и пароль для поддерживаемого способа отправки через SMTP. В программе предусмотрено защищённое соединение на порту 465. Единственный адрес служит одновременно отправителем и получателем. В локальном файле `mail.sqlite` хранится связка «период, почтовый ящик, состояние». Сам текст письма в этот журнал не записывается.

| Что произошло | Состояние и следующий шаг |
| --- | --- |
| Не удалось войти на почтовый сервер | Записи об отправке ещё нет. Исправьте параметры и повторите после проверки. |
| Вход успешен, начата отправка | Программа записывает `pending` перед передачей письма. Эта проверка также предотвращает дубли при одновременных запусках. |
| Сервер принял письмо и результат сохранён | В журнале `sent`. Повтор за тот же период пропускается. Если письма нет во входящих, проверьте папку нежелательной почты. |
| Связь пропала во время передачи или до записи результата | В журнале остаётся `pending`. Автоматический повтор останавливается. Проверьте фактическое письмо по дате и теме. Если результат неясен, используйте локальный HTML до следующего периода. |

Письмо содержит HTML-таблицу в теле и простой текст для клиентов без HTML. Удаление журнала уничтожит сведения о предыдущих отправках на этом компьютере и может породить дубли. Для демонстрации достаточно открыть HTML локально.

## 5. Как провести небольшой эксперимент

Откройте таблицу из учебного прогона сначала в браузере, затем в табличном редакторе. Для каждой строки сравните предмет, действие и срок. Нажмите на источник с учебной ссылкой только если для примера предусмотрена реальная карточка. Вымышленный адрес может служить исключительно образцом. В CSV для одинакового задания источники могут находиться на нескольких строках внутри одной ячейки.

Если CSV открылся в одном столбце, при импорте в редактор задайте разделитель «точка с запятой» и кодировку UTF-8. Если HTML не меняется, убедитесь, что открыт файл именно из папки текущего режима. Если нужен новый статус, изменяйте условия в `table`, затем сравните два старых примера — конфликт и отсутствие срока. Оба формата отчёта должны показывать одно и то же решение.
