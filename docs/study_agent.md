# Что именно делает языковая модель

[Оглавление](README.md) · [Открыть код](../study_agent.py)

Задача модели узкая. Из разрешённых к обработке заметок она выбирает предложения с учебными поручениями. Например, в записи «На занятии повторили ключи. К пятнице подготовьте два примера.» она может выделить «К пятнице подготовьте два примера.» Модель возвращает фрагмент текста, а программа сама проверяет, что этот фрагмент действительно встречается во входной заметке.

## 1. Подготовьте вход

Модуль `extract` принимает выбор поставщика (`codex` или `claude`), путь к закрытой папке проекта и список заметок. В каждой заметке есть текст, предмет, идентификатор и ссылка на источник. Можно потренироваться на такой вымышленной заметке.

```json
{
  "id": "example-1",
  "course": "Базы данных",
  "text": "Сегодня обсуждали индексы. Загрузите схему до 09.11.2026 в 18:00.",
  "url": ""
}
```

При вызове провайдера за пределы компьютера отправляется текст входных заметок и их порядковые номера внутри обрабатываемой группы. Путь к файлам, поля предмета, ID и ссылки не включаются отдельными полями в запрос. **Если вставить имя, e-mail, ссылку или пароль в сам текст заметки, он отправится вместе с текстом.** Используйте свои текстовые формулировки, учебные примеры либо материал, на обработку которого у вас есть необходимые права. Сырые записи из Telegram и личный URL подписки календаря не должны становиться заметками для модели. [Условия использования данных Telegram](https://telegram.org/tos/content-licensing)

## 2. Как проверить отдельный проход по учебным группам

В `classify_demo` зашито короткое вымышленное задание. Даны два предмета и три группы с короткими отрывками. В группе g1 говорят о библиотеке pandas и табличных данных, в g2 — о плане проекта и реестре рисков, в g3 — о прогулке и кафе. Классификатор должен привязать g1 к анализу данных, g2 к управлению проектами и пропустить g3. Сначала классифицируйте строки сами, затем выполните `python study.py classify-demo codex` или замените последнее слово на `claude`. Здесь `classify-demo` означает «проверить классификацию на демонстрационном наборе», а последнее слово выбирает подписку. Команда требует установленного клиента и входа. Она не открывает Telegram.

Программа сверяет каждый ID и название дисциплины с заданным списком, проверяет отсутствие повторов и сравнивает получившееся соответствие с заранее записанным ответом. Модель может верно понять необычное название благодаря короткому отрывку. Результат показывает качество классификации только на этих трёх примерах. В рабочем аккаунте `discover` с помощью локальных правил предлагает совпадения названий, а студент решает, какие группы включать.

## 3. Что происходит при входе

`cli` находит установленную программу по её имени. Если терминал не может найти `codex` или `claude`, дальнейшее выполнение останавливается. Затем модуль готовит для процесса ограниченный набор переменных окружения и отдельную папку учётной записи под `private`. В набор не входят переданные через переменные ключи Telegram, почтовый пароль и ключи платных API.

`authenticate` запускает официальный вход выбранного клиента. У Codex это операция `login`, у Claude Code — `auth login`. Пользователь выбирает свою подписку и завершает вход в предусмотренном поставщиком интерфейсе. Модуль не просит копировать пароль в заметки. Перед извлечением `request` отдельно проверяет, подтверждён ли режим входа. Если проверка не проходит, вызывающий код получает ошибку и не отправляет дайджест с подменённым результатом.

## 4. Как устроен один запрос

1. `extract` делит заметки на группы численностью до восьми. Номера внутри каждой группы начинаются с нуля. Так число `0` в ответе для второй группы означает первую заметку именно второй группы.
2. `request` готовит список пронумерованных текстов. Общая для двух учебных заданий функция `model_json` вызывает клиент с инструкцией для текущего задания и разбирает полученный JSON. Для извлечения задач используется `INSTRUCTIONS`. Она просит выбирать дословные непрерывные цитаты. Фразы внутри материала, даже написанные повелительно, рассматриваются как материал источника.
3. Официальный клиент запускается в отдельной временной рабочей папке и с ограничивающими параметрами. Модель не получает функции сборщика Telegram или отправителя почты. Запросу даётся до четырёх минут, проверке статуса входа — до 30 секунд.
4. Программа читает ответ как JSON. Для каждого элемента списка она проверяет, что `index` — целое число от нуля до номера последней заметки, а `quote` — непустая строка, дословно встречающаяся в тексте указанной заметки. Проверяется регистр букв и пунктуация. Неверная цитата или неправильный формат останавливают обработку.
5. Из локальной исходной заметки возвращаются предмет, ID и ссылка. Функция `exact_due` берёт срок только из самой цитаты. В примере выше итог — «Базы данных», «Загрузите схему до 09.11.2026 в 18:00.», `2026-11-09 18:00`, источник «Личная заметка · example-1».

Пример формата ответа для этой заметки.

```json
{"tasks":[{"index":0,"quote":"Загрузите схему до 09.11.2026 в 18:00."}]}
```

Ответ `{"tasks":[]}` тоже допустим. Это означает, что модель не выбрала цитату. Дословность защищает от приписанной фразы, но не гарантирует полного обнаружения поручений и правильной интерпретации смысла. Например, фраза «Отчёт сдавать не требуется» тоже может дословно встречаться в заметке. Проверяйте такие случаи на своих тестовых примерах.

## 5. Как оценить качество самостоятельно

Подготовьте рядом две свои заметки. В первой дайте два независимых поручения с разными сроками. Во второй опишите уже выполненную работу. До запуска вручную выпишите ожидаемые строки. Затем посмотрите, выбрала ли модель оба поручения, сохранила ли сроки и пропустила ли прошлое действие. После изменения инструкции запускайте тот же набор повторно. Если модель дословно выбрала только половину предложения, проверка формата может пройти, поэтому полноту оценивает человек.

## 6. Что менять при ошибке

| Что случилось | Как искать причину |
| --- | --- |
| Клиент не найден | Следуйте ссылке на установку в основном руководстве. Откройте новый терминал и проверьте, что команда установленного клиента доступна. |
| Вход по подписке не подтверждён | Используйте команду входа именно из проекта. Уже выполненный вход в другом профиле клиента может отличаться. |
| Клиент завершился с ошибкой | Сверьте версию, доступ к сети и лимиты подписки. Если установленная версия не знает ограничивающие параметры, используйте совместимую версию или локальный режим. |
| Ответ не прошёл проверку | Используйте две короткие синтетические заметки и проверьте, выдаёт ли клиент чистый JSON с дословной цитатой. Не отключайте проверку совпадения цитаты ради прохождения примера. |
| Цитата верна, но срок пуст | Проверьте, попала ли в цитату полная дата с годом. Для формулировки «к пятнице» пустое поле ожидаемо. |

Для изменения педагогического задания начните с текста `INSTRUCTIONS`, не с предоставления модели новых инструментов. Доступ к файлам проекта, отправке писем или запуску команд не нужен, чтобы найти в тексте предложение. Отдельную проверку календарной корректности выполняет [модуль правил](study_sources.md).
