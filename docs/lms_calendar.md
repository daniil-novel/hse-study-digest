# Как прочитать срок из календаря SmartLMS

[Оглавление](README.md) · [Открыть код](../lms_calendar.py)

Университет использует [SmartLMS](https://edu.hse.ru/) для домашних работ, тестов и других заданий. Для данного модуля нужен календарь курса с датами заданий. Такой календарь можно читать из локального файла или, если вуз предоставляет личную ссылку, обновлять при каждом запуске. Таблица расписания занятий из HSE App X отвечает на другой вопрос — когда и где проходит пара. Календарь пар не следует подавать на вход этого модуля. [Описание SmartLMS в справочнике ВШЭ](https://www.hse.ru/studyspravka/lms) · [Расписание ВШЭ](https://economics.hse.ru/support/timetable)

## 1. Подготовьте источник

В стандартном Moodle участник открывает «Календарь», выбирает экспорт, события курсов и нужный период. Команда экспорта скачивает файл `.ics`. Команда получения URL формирует личную ссылку, по которой при следующем запросе вернётся актуальный календарь за выбранный диапазон. Если на странице студента в SmartLMS таких команд нет, используйте другой предусмотренный в практикуме источник. Доступ к экспорту в вашей учётной записи проверяется только после корпоративного входа. [Как работает экспорт Moodle](https://docs.moodle.org/en/Using_Calendar)

Выберите один известный срок и откройте карточку задания. Запишите предмет, название, время и часовой пояс. Позже это позволит проверить результат независимо от самого пайплайна. Личная ссылка может содержать секрет доступа даже без запроса пароля. Сохраните её только в закрытых настройках на своём компьютере. Для отчёта подойдёт пример с вымышленной ссылкой.

## 2. Как до программы доходят данные

`read_tasks(location, courses)` получает два аргумента. Первый указывает, откуда брать календарь. Второй — словарь предметов из ИУП с дополнительными названиями. В начале работы функция подключает пакет `icalendar`, который понимает структуру календарного файла. Для других частей базового практикума этот пакет не обязателен.

1. `calendar_bytes` открывает локальный путь или скачивает календарь. Относительный путь отсчитывается от корня проекта. Для подписки разрешён HTTPS-адрес `edu.hse.ru/calendar/export_execute.php`. Переход на другую страницу блокируется классом `NoRedirect`. Поэтому перенаправление на страницу входа даст понятную ошибку.
2. Выполняются две проверки. Ответ должен начинаться с `BEGIN:VCALENDAR` и содержать не более 5 000 000 байт. Веб-страница с формой входа не будет принята за пустой календарь.
3. `Calendar.from_ical` разбирает байты в события. `calendar.walk()` даёт прочитать каждую вложенную запись. Модуль игнорирует другие части, например определения часовых поясов, как самостоятельные задачи.
4. Для объекта `VTODO` используется поле `DUE` (срок задачи). Для `VEVENT` используется начало `DTSTART`, но только если в заголовке есть явное указание на срок, например «Дедлайн» или «срок сдачи». Просто «Семинар» при обработке пропускается. Выражение `NOT_DUE` также отсекает обсуждения, напоминания и некоторые другие фразы, например «дедлайна нет». Уже завершённые и отменённые записи тоже пропускаются.
5. В названии, описании и категориях программа ищет полное имя или сокращение дисциплины. Нужен ровно один совпавший предмет. Если совпадений ноль или несколько, запись пропускается с итоговым предупреждением. Повторяющиеся события с правилом `RRULE` также идут в это предупреждение. Они требуют отдельно разбирать серию и её исключения.
6. Если срок включает часовой пояс, время переводится в московское. Например, `15:00 UTC` станет `18:00` МСК. Если известно только число, то и в таблице останется только дата. Если время задано без часового пояса, срок оставляется пустым, чтобы студент проверил его в курсе.
7. По идентификатору `UID` вычисляется короткая метка источника. Если в записи нет `UID`, основой служат предмет, заголовок и срок. `card_url` сохраняет только ссылку на поддерживаемую карточку задания, теста или семинара Moodle с числовым `id`. Лишние параметры ссылки, в том числе ключи доступа, не попадают в таблицу. При отсутствии распознанной ссылки на карточку используется обычная страница календаря SmartLMS.

## 3. Проследите одну запись от начала до конца

Пример фрагмента учебного файла. `Z` в конце календарной даты означает время UTC.

```text
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//Учебный пример//RU
BEGIN:VEVENT
UID:demo-lab-1@example.test
DTSTAMP:20261101T120000Z
DTSTART:20261109T150000Z
SUMMARY:Базы данных — срок сдачи лабораторной
END:VEVENT
END:VCALENDAR
```

Со словарём `{"Базы данных": ["БД"]}` программа найдёт один предмет. Слова «срок сдачи» позволяют использовать начало события как срок, поэтому в поле `due` окажется `2026-11-09 18:00`. В поле `url` будет общая страница календаря SmartLMS, потому что в примере нет ссылки на карточку. Замените слова «срок сдачи лабораторной» на «лекция». При том же времени и предмете задача исчезнет.

Для локальной проверки сохраните вымышленный пример как `private/lesson.ics`. Если редактор спрашивает о кодировке, выберите UTF-8. В терминале из корня проекта выполните следующую команду.

```text
python -m pip install -r requirements-calendar.txt
```

`python` запускает выбранную версию Python. Параметр `-m` запускает модуль установщика `pip`. Слово `install` просит установить пакеты, а `-r` сообщает, что список пакетов нужно прочитать из указанного файла. Интернет требуется только для установки. Затем введите `python`, дождитесь `>>>` и выполните строки по одной.

```python
from lms_calendar import read_tasks
rows = read_tasks("private/lesson.ics", {"Базы данных": ["БД"]})
print(rows[0]["due"])
exit()
```

Первая строка подключает функцию. Вторая сохраняет список её результатов под именем `rows`. Третья выводит поле срока первой записи. В Python счёт элементов начинается с нуля. Должно появиться `2026-11-09 18:00`. Последняя строка закрывает интерпретатор. Если после замены заголовка на «лекция» список пуст, смотрите `print(rows)` вместо обращения к первому элементу.

Готовый похожий файл лежит в [examples/deadlines.ics](../examples/deadlines.ics). Там две записи по предмету «Алгоритмы». UTC-срок 17:59 должен стать 20:59 МСК, а лекция не должна появиться среди заданий. Этот случай закреплён в [тестах календаря](test_lms_calendar.md).

## 4. Как отладить реальный источник

| Наблюдение | Что делать |
| --- | --- |
| «Не удалось прочитать календарь» | Проверьте расположение файла или снова откройте экспорт в своей учётной записи. Персональную ссылку никому не пересылайте. |
| «Ожидался файл iCalendar» | Первой строкой текстового файла должно быть `BEGIN:VCALENDAR`. Скачанная HTML-страница входа не содержит календаря. |
| Источник открылся, но заданий меньше, чем в курсе | Сверьте диапазон экспорта. Проверьте, внесён ли дедлайн преподавателем в календарь, как он озаглавлен и есть ли в записи название курса. Прочие записи не объявляются выполненными. |
| Есть предупреждение о пропуске | Найдите пропущенную запись. Для короткого кода курса, стоящего в категории, при необходимости добавьте явный псевдоним. Серийное событие проверьте вручную. |
| В курсе перенесли срок, в отчёте остался старый | Проверьте источник. Локальный файл показывает состояние на момент скачивания, его надо заново экспортировать. При подписке проверьте фактическое событие в самой ленте и дату очередного запуска. |
| Ссылка открывает общий календарь | В событии нет распознанного адреса конкретной карточки. Найдите запись по предмету и заголовку. |

Чтобы добавить новую формулировку срока, сначала найдите в карточке реальный смысл календарного события. Воспроизведите его на вымышленной записи и лишь затем измените выражение `DUE`. Отдельно проверьте событие с формулировкой «начало приёма». Такая запись не должна превратиться в крайний срок.
