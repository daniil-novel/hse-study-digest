# Как проверяется цепочка без личных аккаунтов

[Оглавление](README.md) · [Открыть тесты](../tests/test_digest.py)

В файле `tests/test_digest.py` каждый метод с именем `test_…` проверяет отдельное обещание программы. Тест создаёт заранее известный вход, вызывает настоящую проверяемую функцию и сравнивает результат с ожидаемым. Чтобы испытание не отправляло письма и не читало чужой чат, там, где нужен внешний сервис, вместо него используется управляемая имитация.

## Как запустить

В терминале из корня проекта введите команду.

```text
python -m unittest discover -s tests -p test_digest.py -v
```

`python -m unittest` запускает встроенный в Python модуль проверки. `discover` просит найти тесты. Параметр `-s tests` задаёт папку, `-p test_digest.py` ограничивает поиск одним файлом, `-v` показывает название каждой проверки. В конце `OK` сообщает об успехе. При `FAIL` программа получила неожиданный результат, а `ERROR` означает, что проверка не смогла завершиться.

## Что проверять в результатах

| Часть имени теста | Вход и ожидаемое наблюдение |
| --- | --- |
| `demo_is_offline_repeatable_and_keeps_evidence` | Два прогона одной вымышленной выборки дают одинаковые байты CSV, четыре строки и два источника у лабораторной. Два противоречащих срока остаются видны, относительный срок не получает даты, архивные и личные сообщения отсутствуют. |
| `calendar_boundaries_and_dates` | Проверяются високосный февраль и переход через Новый год. Правильная дата разбирается, а «завтра», несуществующий день, неправильно записанное время, перенос или внешний часовой пояс не превращаются в точный срок. |
| `discovery_reads_metadata_and_reports_ambiguous_courses` | Два сокращения в названии дают два предмета-кандидата. Имитация Telegram возвращает активную группу, старую группу и личный диалог. Кандидатом остаётся только активная группа. У проверяемой команды запрошено не более 300 диалогов. |
| `provider_gets_approved_text_only_and_verifies_exact_quote` | Вместо клиента модели возвращается вымышленный JSON. Проверяются распознанный срок, отсутствие отдельных полей ID, предмета и ссылки в запросе, исключение ряда переменных среды и отклонение выдуманной цитаты. |
| `live_reader_requests_only_explicit_group_and_honors_cutoff` | Имитация клиента запоминает ID группы, к которой обратился сборщик. В выдаче остаются сообщение точно на временной границе и более новое сообщение, более старое пропускается. Положительный ID личного чата отклоняется. |
| `classifier_has_only_synthetic_inputs_and_checks_ids` | Проверяется отдельно демонстрационный проход модели по трём вымышленным группам и отказ обработки ответа, содержащего посторонний ID. |
| `expired_claude_login_explained_without_exposing_stdout` | Искусственно создаётся ошибка истёкшей сессии. Пользователь получает команду для повторного входа, а содержимое диагностического ответа не раскрывается. |
| `mail_is_self_only_and_ambiguous_sends_do_not_retry` | Имитация почтового сервера подтверждает доставку, а затем в отдельном случае имитирует обрыв соединения. В обоих сценариях за период делается только одна попытка передачи сообщения. Адресат — собственный ящик. |
| `live_merges_streams_only_after_extraction` | Тест добавляет синтетическую запись Telegram и свою заметку. Модель получает только отдельную заметку, а итоговая таблица всё-таки содержит запись из Telegram. |
| `spreadsheet_html_and_feed_url_protection` | Текст `=1+1` защищён как текст в CSV. Личный адрес календаря с токеном и ссылка с небезопасной схемой не проходят фильтр ссылок. Поддерживаемая ссылка на сообщение проходит. |

## В какой тест смотреть после изменения

Хотите изменить фильтр активности — начните с `calendar_boundaries_and_dates` и `discovery…`. Исправляете формат подсказки для модели — проверьте `provider…` и `live_merges…`. Меняете антидублирование писем — `mail…`. Если ожидаемая строка изменилась, сравните поведение до и после. Сначала найдите причину расхождения и проверьте её на одном предложении. Подгонка ожидаемого результата под случайный вывод лишит тест смысла.

Успех этих тестов говорит о поведении кода в контролируемых условиях. Для проверки своих подключений нужны отдельные наблюдения — успешный вход, сверка известного задания и фактически полученное тестовое письмо. Проверки календарного файла описаны [отдельно](test_lms_calendar.md).
