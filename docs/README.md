## Порядок чтения исходников

1. [`digest.py`](../digest.py) связывает команды пользователя с функциями.
2. [`digest_config.py`](../digest_config.py) читает настройки и сохраняет выбор чатов.
3. [`telegram_stdio.py`](../telegram_stdio.py) общается с публичным MCP, а [`local_digest.py`](../local_digest.py) и [`telegram_agent.py`](../telegram_agent.py) представляют два способа обработки.
4. [`agent_code/knowledge.py`](../agent_code/knowledge.py) превращает результаты сборов в долговременные карточки.
5. [`study_report.py`](../study_report.py) строит таблицу и отправляет письмо; [`digest_schedule.py`](../digest_schedule.py) вычисляет нужные моменты.
6. [`agent_code/service.py`](../agent_code/service.py) повторяет отдельные рабочие команды. [`runtime.py`](../agent_code/runtime.py) загружает только разрешённые секреты, [`skills.py`](../agent_code/skills.py) подключает инструкции навыков.

Модули Smart LMS — [`lms_calendar.py`](../lms_calendar.py), [`lms_api.py`](../lms_api.py) и небольшой [`study.py`](../study.py). Подписочные инструменты вызываются через [`study_agent.py`](../study_agent.py). Общие правила текста и дат находятся в [`study_sources.py`](../study_sources.py).

## Навыки и проверка

Три [навыка проекта](../skills) разделяют сбор, поиск и обслуживание. Их исходные `SKILL.md` доступны для чтения. Установку в папку проекта делает команда `install-skills`; программные вызовы дополнительно загружают нужные инструкции непосредственно из исходных файлов.

[Тесты](../tests) проверяют ограничения доступа, календарь, состояние реестра, версии базы, цитаты, расписание и фоновую работу. Встроенные тестовые данные нужны для автоматической проверки кода; маршрут студента работает с его собственными настоящими источниками. Прохождение тестов не подтверждает актуальность отдельного аккаунта Telegram, доступность SMTP или разрешение передать материал модели — это проверяется при подключении.
