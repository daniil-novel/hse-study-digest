# Путеводитель по программе

Начинайте с [практикума по macOS](macos.md), если ваша цель — запустить дайджест. Эта страница поможет найти место в исходниках, когда вы хотите изменить поведение или объяснить его на защите. [Схема архитектуры, последовательность вызовов и исходники Excalidraw](diagrams/README.md)

## Откуда берётся одна строка

Если вам нужен конкретный файл, откройте [подробную главу о семи модулях](modules.md). Каждый раздел содержит вход и ожидаемый выход, порядок чтения функций, пример доработки и связанные тесты. Вспомогательные модули описаны отдельно: [парсер и даты](legacy/windows/docs/study_sources.md), [CLI](legacy/windows/docs/study_agent.md), [сборка отчёта и почта](legacy/windows/docs/study_report.md), [импорт ICS](legacy/windows/docs/lms_calendar.md) и [Smart LMS REST](legacy/windows/docs/lms_api.md). Эти пять ссылок ведут на материалы зафиксированной предыдущей версии; текущие команды есть в руководстве macOS.

Допустим, в разрешённой группе «Семинар наставника 25/26» опубликован вымышленный текст «Подготовьте презентацию до 20.11.2026». Студент связал точный заголовок с предметом «Семинар наставника» в `[local.chat_titles]` и установил `mode = "local"`.

1. **Поиск и проверка разрешений.** Локальный клиент запускает сервер, запрашивает список доступных инструментов и проверяет, что они предназначены для чтения. Из каталога остаются дата последней активности, ID, тип и заголовок. Локальная ветка отбирает предмет и учитывает постоянный реестр исключений.
2. **Чтение.** Клиент вызывает `messages_between` с ID разрешённого чата, началом и концом интервала. Большой ответ читается по страницам. При своём повторном чтении программа проверяет доступность источника.
3. **Разбор текста.** Локальная функция ищет признак поручения и объект «презентация», затем распознаёт дату. Она возвращает пару «Подготовить презентацию» и «2026-11-20». Эти слова берутся из словаря проекта. Просмотр и исходное предложение не становятся описанием поручения в локальном отчёте.
4. **Оформление.** Программа дополняет пару предметом, названием источника или выбранным обозначением, номером сообщения и доступной ссылкой. HTML и CSV используют общие строки.
5. **Доставка.** Если вы разрешили отправку и наступил подходящий момент, одно письмо на ваш адрес получает сводку и CSV-вложение. Только после подтверждения почтового сервера сохраняется отметка об успешной передаче.

В облачной ветке шаги 2–3 меняются. Модель запрашивает разрешённый образец, классифицирует группу и выделяет цитату. Локальный шлюз проверяет наличие этой цитаты в возвращённом сообщении. Провайдер получает выбранный текст; это отдельная граница доступа, которая показана на второй схеме.

## Какой файл открыть

| Файл | Что получает и возвращает | На каком примере разобраться |
|---|---|---|
| [digest.py](../digest.py) | Читает название команды из Терминала и последовательно вызывает нужные модули. Разводит локальный, облачный, учебный и почтовый сценарии | Найдите ветки `run` и `tick`. Почему просмотр таблицы не отправляет письмо? |
| [digest_config.py](../digest_config.py) | Копирует шаблоны в закрытую папку, разбирает TOML, проверяет типы и обновляет реестр с сохранением комментариев | В `merge` найдите условия включения нового ID. За счёт какого списка ручное удаление переживает перезапуск? |
| [telegram_stdio.py](../telegram_stdio.py) | Находит исполняемый MCP, согласует протокол, читает страницы разрешённых методов, проверяет источник и курсор продолжения | В функции `catalog` сравните поля ответа upstream с теми, которые остаются после локального отбора |
| [local_digest.py](../local_digest.py) | Сопоставляет живые группы с предметом, получает сообщения и превращает текст в фиксированные категории и сроки | В `tasks_from_message` найдите, почему вопросительный текст пропускается. Затем добавьте категорию из учебного опыта |
| [local_plan.py](../local_plan.py) | `make_plan` передаёт подписочной модели встроенные учебные фразы и фиксированный словарь. После проверки сохраняет правила в `private/plan-local.toml`. `load_rules` загружает их для локального применения | Запустите `plan-local`, откройте созданный TOML и объясните, в какой момент модель закончила свою работу и какие записи позднее обрабатываются только на Mac |
| [telegram_agent.py](../telegram_agent.py) | Проверяет область разрешения, отправляет разрешённый контекст выбранному CLI, проверяет ответы, записывает доказательства отбора | Проследите, где прекращается сбор, если появился неподтверждённый отправитель. Какие данные хранятся только локально? |
| [study_agent.py](../study_agent.py) | Запускает CLI с отдельным профилем авторизации, передаёт ему инструкцию и данные и принимает структурированный ответ | Найдите создание окружения дочернего процесса и проверку подписочного входа. Telegram-сессия и SMTP-пароль для этого вызова не нужны |
| [study_sources.py](../study_sources.py) | Содержит общие правила двух календарных месяцев, сопоставления названий и распознавания точной даты из текста | Сравните `20.11.2026` и «на следующей неделе». В файле также есть адаптер Telegram для архивного маршрута Windows; основной сценарий macOS использует MCP |
| [study_report.py](../study_report.py) | Из нормализованных строк формирует HTML/CSV, аккуратно публикует разрешённые ссылки и ведёт состояние почтовой передачи | Найдите строку с двумя разными сроками, затем логику создания CSV-вложения. Разберите, почему неизвестный ответ SMTP не означает, что можно отправить ещё раз |
| [digest_schedule.py](../digest_schedule.py) | Превращает режим, календарные дни и время из TOML в моменты запуска. Регистрирует и снимает пользовательское задание macOS | Сравните месячное правило `[31]` с `[-1]` в феврале, проверьте `upcoming` и `due` |
| [lms_calendar.py](../lms_calendar.py) | Принимает локальный ICS или выданную защищённую ссылку ВШЭ, отбирает события курса со сроком и переводит время в МСК | В [учебном календаре](../examples/deadlines.ics) есть лекция и отчёт: в таблицу должен попасть только отчёт |
| [lms_api.py](../lms_api.py) | При наличии выданного вузом токена запрашивает разрешённый метод Moodle, превращает подходящие события в те же строки | Найдите вызов календарных событий курса и ошибку отсутствующего токена. Чтение под своей ролью требует реально выданных вузом прав |

## Где хранятся настройки, доказательства и тесты

- **Шаблоны для человека** лежат в [templates](../templates). `init` создаёт персональные настройки в `private`. Набор полей основного TOML и подписки модели остаётся виден до первого сетевого запуска.
- **Учебный и рабочий выходы** разделены. В `out/mcp-demo` можно показать работу синтетического MCP. В `out/live` лежит результат настоящего сбора, включая личные заметки. Закрытые папки в открытый репозиторий не входят.
- **Тесты** находятся в [tests](../tests). Здесь можно найти проверку границ доступа, конфликтов сроков, расписания и календаря. Читайте каждую проверку в порядке «вход → действие → ожидание». Так проще отличить факт, который тест действительно проверяет, от предположения о реальной доставке.
- **Архив Windows** содержит прежний подробный разбор и ссылку на соответствующий ему зафиксированный исходный код. Названия команд и конфигурация архива отличаются. [Прежний практикум](legacy/windows/README.md)
